GTM Signal Intelligence Platform

▶ Live Product
FastAPI Python Supabase Groq LLM React GitHub Actions Telegram Vercel

A competitive intelligence platform that monitors 4 AI coding tools (Cursor, Windsurf, GitHub Copilot, Codeium) across Reddit, HackerNews, and official changelogs. Every signal is processed by a Groq LLM for structured extraction, scored by business impact (High / Medium / Low), and delivered automatically via a daily Telegram digest and a live public dashboard. Runs on a GitHub Actions cron every morning at 08:00 UTC with no manual intervention. The dashboard's Refresh Now button dispatches a real pipeline run via the GitHub API. No server costs, no polling. Total monthly infrastructure cost: $0.

Built the full stack independently: FastAPI backend with REST endpoints, Supabase PostgreSQL with upsert deduplication, four scrapers across different source types (REST APIs, HTML parsing, community forums), LLM prompt engineering for classification and impact scoring, and a React frontend with custom animation systems. Went through 20+ production debugging cycles including dependency conflicts, RLS blocking writes, Groq returning malformed JSON, and scoring calibration across three iterations.

GTM Automation Stack

▶ In Production
Claude API Make Apollo Apify Mailmeteor n8n Puppeteer Python REST APIs

A personal end-to-end outbound automation pipeline built from scratch and running in production for over a year. Apify handles daily prospect sourcing, Apollo runs waterfall enrichment, and a Puppeteer layer calls the Claude API to research each account, build multi-source context, and generate personalized outreach copy per record with structured output constraints and fallback logic. Make orchestrates the full pipeline with branching logic, error handling, retries, and webhook triggers.

Diagnosed and resolved three post-launch failure classes: silent Puppeteer DOM failures passing empty fields downstream, Claude hallucinating on incomplete inputs (fixed with structured output schema), and Make masking partial API errors as successes (fixed with secondary output validation per module). Each fix is documented.
